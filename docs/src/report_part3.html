5.6 已知简化与局限

  • 重叠班次工时重复计入：当错误级重叠已存在时，日/周工时按记录逐条累加，重叠时段会被重复计入合计；系统通过 R1 规则显著标出重叠以便人工核实，未做去重合并；
  • 单账号、无并发控制：已实现管理员密码登录（会话 7 天），但按单店长使用设计，无多账号与并发写保护；
  • 无操作审计：调班、删除暂无历史留痕（数据库备份可作时点恢复）；
  • 开发服务器：未做生产部署加固（HTTPS、WSGI 服务器、进程守护）；
  • 可用时段仅支持“每日一段”窗口：不支持同一员工一天内多段可用时间，跨日班次与窗口组合存在场景限制（如跨日班次必超当日窗口，需为夜班员工留空时段约束）。

6 总结与展望

6.1 工作总结

本项目完成了一个面向中小团队排班场景的完整技术原型，主要工作包括：

  • 需求层面：从手工/Excel 排班的四个具体痛点出发，定义了 7 项功能需求、5 类可配置冲突规则与相称的非功能需求，明确了本阶段范围边界；
  • 设计层面：完成三层架构与 4 表数据库设计；确立“排班记录为工时唯一数据源”“跨日归开始日期”“错误级阻断/提示级可见”三项关键设计决策；按 Material 3 规范建立米 beige 设计令牌体系并落地为可复用组件样式；
  • 实现层面：交付可运行的 Flask + SQLite 原型（约 3400 行源码），覆盖员工管理、班次模板、周视图排班、五类冲突检测、日/周/月工时统计、Excel 报表导出、规则配置、备份与管理员密码登录；核心逻辑以纯函数实现，与框架解耦；
  • 验证层面：58 项自动化测试全部通过（含登录保护、错误密码、改密校验、限速等认证场景），覆盖正常排班、重叠、不可用时间、工时上限、跨日、休息扣除、周期边界与导出等竞赛要求场景；以脚本实测原型规模下页面响应 P95 ≤ 40 毫秒、导出 P95 ≤ 110 毫秒；
  • 成果物：可运行软件与源代码、技术研究报告（本文）、9 张真实运行截图、性能测量记录、演示视频脚本（附录 D）。

6.2 不足

原型仍有明显局限：单管理员账号、无员工自助与分角色权限；重叠时段工时重复计入；无操作审计；可用时段仅支持每日一段；未开展真实用户评估与并发测试。上述已在 5.6 节如实说明，均不影响本阶段功能验证的有效性。

CREATE INDEX IF NOT EXISTS idx_schedules_emp_date ON schedules(employee_id, work_date);
